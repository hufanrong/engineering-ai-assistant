# WORKbuddy 本地实测手册 · 繁工AI v0.1.176

这份手册给 WORKbuddy 用。目标只有一件事：**把最新安装包装在用户本地电脑上，代替用户把真实工作走一遍，然后把实测数据回传给 AI 侧**。AI 侧只依据回传的数字改代码，所以数字必须是真的，不能猜、不能估算、不能拿上一轮的结果顶替。

---

## 零、这一轮要交回什么（先看结果，再看过程）

回传**三份文件**，缺一不可：

| 文件 | 位置（安装目录内） | 内容 |
|---|---|---|
| `verify_install.json` | `tools\verify_install.json` | 装得对不对：Python、依赖、版本号、模板、目录权限、端口 |
| `fieldtest_report.json` | `tools\fieldtest_report.json` | 用真实资料走完一遍业务的每一步实际数字 |
| `fieldtest_report.md` | `tools\fieldtest_report.md` | 同上，人能直接读的版本 |

**外加一段文字**，只写三件事：

1. 哪一步失败或降级了（贴原始报错，不要改写）；
2. 用的什么资料（台账来源、登记表来源、资料目录里有多少个文件）；
3. 你觉得哪里用起来别扭——这是最有价值的部分，代码测不出来。

## 一、装包（不要用旧代码，必须用这一版）

安装包：`繁工AI_v0.1.176_安装包.zip`

```bat
:: 1) 解压到一个干净目录（不要覆盖旧安装，避免新旧文件混在一起）
::    例如解压到 D:\fangong-workbench-v0176

:: 2) 进目录，装依赖（首次约 3~8 分钟，取决于网络）
cd /d "D:\fangong-workbench-v0176\fangong-workbench"
install.bat
```

`install.bat` 会建 `.venv` 并 `pip install -r requirements.txt`。装完**先别启动服务**，先做第 2 步自检。

> 如果这台机器上原来就有旧版在跑，先把它关掉（窗口关掉即可），否则 8756 端口会被占。自检会提示端口被占，那不是缺陷，是上一次没关。

## 二、验装（服务不启动也能跑）

```bat
cd /d "D:\fangong-workbench-v0176\fangong-workbench"
python tools\verify_install.py
```

判定：

- **退出码 0** 且末尾打印「安装自检通过」→ 继续第 3 步。
- 有 `[FAIL]` → **停下来，把 `tools\verify_install.json` 全文回传**，不要继续往下测。装坏了再测业务，测出来的失败都不可信。
- `[SKIP]` 不算失败。两个常见 SKIP：可选依赖没装（向量检索会降级成关键词检索，这是设计内行为）、端口空闲。

沙箱内对照值（干净 Linux 环境实测）：**通过 7 / 失败 0 / 跳过 2**。你机器上的数字应该接近，不必一致。

## 三、启动工作台

```bat
run_workbench.bat
```

它会 `python start.py` 并自动打开 `http://127.0.0.1:8756`。看到界面就说明起来了。**这个窗口不要关**，下一步要连着它跑。

## 四、代替用户做真实操作（核心步骤）

这一步是「代替用户操做完成本地实际操做」。**必须用用户自己的真实资料**，不能用示例文件，否则测不出真问题。

先确认三样材料在不在（用户说过它们在本机）：

| 材料 | 说明 | 在哪 |
|---|---|---|
| 设备台账 | xlsx/csv，用户的真实台账 | 用户本地已有一份，问清路径 |
| 整编要求登记表 | 监理给的登记表格式，用户的真实那份（约 214 项） | 用户项目目录里已跑好的那份 |
| 资料目录 | 现有工程资料（方案、记录、图纸等） | 用户的工作目录 |

找到后执行（路径按实际改，**中文路径要加引号**）：

```bat
cd /d "D:\fangong-workbench-v0176\fangong-workbench"
python tools\fieldtest.py ^
  --ledger "D:\工程\设备台账.xlsx" ^
  --registry "D:\工程\整编要求登记表.xlsx" ^
  --docs "D:\工程\资料" ^
  --book 第一册 ^
  --workshop 1号车间 ^
  --keep
```

参数说明：

- `--ledger` **必填**。没有台账，整卷出的全是空表头，测不出任何真实问题。
- `--registry` 不填会用内置的 3 项最小登记表，**那样只能证明链路通，不能证明用户那份 214 项登记表能解析**——报告里这一项会标 SKIP，别当成通过。
- `--docs` 把真实资料目录扫进库，验证解析率与自动归车间。
- `--keep` 保留现场，跑完能自己打开成品看。**这一轮务必加**，AI 侧要靠成品文件定位问题。

脚本会按真实工作顺序走完：建项目 → 导入台账 → 扫描资料 → 解析 → 归车间 → 检索 → 预填 → 生成 Word → 导登记表 → 一键整卷 → 打开成品 → 一键竣工 → 换项目验隔离 → 导出成品包。

跑完输出三行结论（`通过 N / 失败 N / 跳过 N`），并把两个报告写进 `tools\`。

沙箱内对照值（干净安装 + 5 台设备的小台账实测）：**通过 32 / 失败 0 / 跳过 5**。你机器上的通过数会因为真实台账更大、登记表项更多而更高，这是正常的。

> 如果工作台服务起不来（例如依赖装到一半失败），fieldtest 支持进程内模式：加 `--inproc` 会直接调路由、不依赖后台服务。但**这一轮请优先用正常模式**——用户真实使用的就是有服务的形态，进程内模式测不出端口、启动、浏览器这条真实链路。

## 五、跑完自己先看一遍（别把明显的坏结果回传）

`--keep` 之后，测试项目留在 `data\projects\<id>\volumes\<册名>\<车间>\` 下。打开目录做五件事：

### 5.1 成稿不许有模板变量残留

用 Word 打开生成的 `.docx`，看表格里设备行对不对、有没有 `{{模板变量}}` 残留。残留应该是 **0 处**；未填的字段应当显示成 `【待补充】`。看到 `{{施工单位}}` 这种原文，就是缺陷，把文件名记下来回传。

沙箱内对照：两份成品 docx 正文 `{{` 残留 **0 处**，`【待补充】` 标记 **17 处**。

### 5.2 卷内目录的页次必须和你看到的真实页数一致（本轮重点）

打开 `_卷内目录.docx`，对着每一行做这件事：

1. 用 Word 打开同一目录下那个 `.docx` 成品文件；
2. 看 Word 窗口左下角状态栏的「第 X 页 / 共 Y 页」，记下 **Y**；
3. 回到卷内目录，核对那一行的「页次」格子。

判定标准：

- 页次写成 `起页-止页`，例如第一份文件 `1-9`、第二份 `10-18`，说明起止是连续的、没有重叠也没有空洞；
- **止页 − 起页 + 1 必须等于你在 Word 里看到的该文件真实页数**；
- 最后一份的止页，必须等于「本卷共 N 份文件，合计 X 页」里的 **X**。

沙箱内对照（LibreOffice 渲染实测）：`1_设备开箱检查记录.docx` = 9 页，`2_设备安装检查记录.docx` = 9 页，卷内目录写 `1-9` / `10-18`，合计 **18 页**，与独立再渲一次的 9+9 完全一致。

**如果页次格子里写的是「未计算」**，说明这台机器既没有 Word COM 也没有 LibreOffice。Windows + 装了 Word 的机器应当走 `doc.ComputeStatistics(2)` 拿到真实页数——**如果在这种机器上也显示「未计算」，就是缺陷，务必回传**，并附上 `pip list` 里有没有 `pywin32`。

### 5.3 案卷封面与备考表

打开 `_案卷封面.docx` 和 `_卷内备考表.docx`，核对：

- 案卷题名 = `<册名>　<车间>`；
- 备考表里的「本卷文件件数」「本卷页数」是否和卷内目录的合计一致；
- 档号、编制单位、立卷人、检查人显示成 `【待补充】` 是**正常**的——这些是用户单位自己的信息，系统不编造，由人填。

### 5.4 装盒清单

打开册目录下的 `_装盒清单.xlsx`，核对：一册下每个车间一行，件数与页数和卷内目录对得上。

沙箱内对照：`第1盒 | 第一册 | 1号车间 | 2 | 18 | 渲染实测 | 0 | 第一册／1号车间／共2件`。

### 5.5 换个项目再整一次卷（本轮重点验收）

v0.1.176 把 24 个模块的业务数据全部改成落项目目录，这一条必须实测：

1. 在项目 A 里录一条施工日志、一条隐蔽验收、一条吊装方案（界面上点生成即可）；
2. 新建项目 B，切过去，逐个打开这三个列表；
3. **B 里必须是空的**。如果能看到 A 的记录，就是隔离没做到位，把功能名回传。

再往下做两件确认：

4. 在 B 里录一条，切回 A，A 里不应出现 B 那条；
5. 关掉程序重新打开（验证落盘，不是内存里装着）。

同时打开 `data\projects\<A的id>\` 和 `data\projects\<B的id>\` 两个目录对比：业务 json（如 `site_logs.json`）应当只出现在各自项目目录里，**全局 `data\` 根目录下不应该再新出现这些文件**。

## 七、这一版改了什么

在 v0.1.174 修掉「模板变量残留在成稿」的基础上，这一版补上了**阶段③ 竣工资料组卷的收尾部分**：

| 新增产物 | 作用 |
|---|---|
| `_卷内目录.docx` | 按登记表的册/序号排序，列：序号、文件编号、资料名称、表号、页次、编制单位 |
| `_案卷封面.docx` | 档号、案卷号、案卷题名、编制单位、编制日期、保管期限、密级 |
| `_卷内备考表.docx` | 本卷件数、页数、未生成项、本卷情况说明、立卷人、检查人 |
| `_装盒清单.xlsx` | 按册汇总：盒号、册、车间、件数、页数、页数依据、未生成项、脊背标签建议 |

关键点：**页次是真实渲染出来的页数，不是估算的**。顺序是 Windows Word COM（`doc.ComputeStatistics(2)`）→ LibreOffice 转 PDF 再数页 → 都拿不到就如实写「未计算」并注明原因。绝不按「一份算一页」糊弄——页次要印在交给监理的正式目录上，估错了整个卷的索引就错位。

另外，登记表里有、但还没生成的项会以「尚未生成」出现在卷内目录末尾并计数，不会假装成已完成。

**v0.1.176 这一版的主改动是跨项目隔离**（这就是第 5.5 步要验收的内容）：

- 24 个模块（施工日志、隐蔽验收、开箱记录、损坏报告、设计变更、安装方案、吊装方案、技术交底、施工进度、进度增强、进度优化、竣工归档、以及 11 个合并模块）原来统一写全局 `data\`，现在全部落当前项目目录；
- **没有选中项目时直接拒绝写入**并给出明确提示，不再悄悄写到一个没有归属的地方；
- 老机器上全局 `data\` 里的历史数据，第一次被某个项目访问时复制进那个项目（只复制、不删除、只做一次），避免历史数据凭空消失。

沙箱实测：24/24 模块隔离正确；项目 B 目录里没有一条项目 A 的业务数据；无项目时写入被拒且全局 `data\` 未被创建。

## 八、已知限制（别当成缺陷）

- **跨项目数据串味（本版已修，需你实测确认）**：v0.1.176 把 24 个模块（施工日志、隐蔽验收、吊装方案、安装方案、进度、各类 `*_merge` 等）的数据改为落项目目录，无项目时直接拒绝写入。沙箱内逐模块验证 24/24 隔离正确、B 项目目录里没有任何 A 的业务文件。**你按第 5.5 步实测一遍，有任何一个功能还能串，就回传功能名。**
- **老机器历史数据迁移**：旧版写在全局 `data\` 里的历史业务数据，会在**第一次**被某个项目访问时复制进那个项目目录，之后不再复制（避免把串味变成默认行为）。所以第一次打开旧项目时如果看到历史记录、而新项目里看不到，是预期行为。
- **向量检索降级**：没装 `sentence-transformers` / `chromadb` 时，检索走关键词匹配，报告里 `retrieval=keyword`。这是设计内降级。
- **CAD 图纸只登记不解析**：没装 `ezdxf` / ODA File Converter 时如此。
- **阶段④ 竣工图清稿**需要 Windows + AutoCAD + `pywin32`。本机装了 AutoCAD 才能测；装不了会 SKIP，不是失败。
- **空壳拦截是有意行为**：某车间有设备，但模板里没有覆盖该设备类型的表时，系统会拒绝产出空表并把「哪台设备没被接住」列出来。报告里 `空壳=N` 通常说明模板缺表，不是程序坏了。
