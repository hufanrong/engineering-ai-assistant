## 二、三种病根（不是一个问题，必须分开治）

### 病根 A：单字后缀 + 惰性匹配 → 把长词切成前缀

代码位置：`workbench/app/workshop_assign.py:127`

```python
_WORKSHOP_RE = re.compile(
    r"|(?P<name>[\u4e00-\u9fa5]{1,8}?)(?:车间|厂房|库房|配电室|化验室|控制室|变电站|配电站|泵站|堆场|料场|库|室|间|仓|房|站|场|区|厂)"
)
```

`{1,8}?` 是**惰性**的，后缀集里又包含 `室/间/站/厂/区/场/仓/房` 这些**极常见的单字**。
于是正则从最左端、用最短的名字去凑后缀，只要凑上就成立。

实测原文（`7df8d3ccd3dc…防雷接地….dwg`，解析缓存里的真实文本）：

```
… 预埋不锈钢端子板
100X100X6mm,
相对室外地坪高度        ← 这一整行的真实内容
0.5m,
…
```

- 正则匹配「相对」+「室」= **相对室**，`m.start()` 正好在第 0 位
- 于是「行首」闸通过
- 该行长度 8 字 ≤ 40，于是「短行」闸也通过

同类：`件与件之间` ← 原文

```
技术要求:
件与件之间采用焊接连接，焊接要求应符合GB50205的规定；1.
```

正则匹配「件与件之」+「间」= **件与件之间**，同样是行首、同样 ≤40 字。

> **为什么 v0.1.227 加的两道闸（行首 + 40 字短行）拦不住**
> 这两道闸约束的是「命中在行内的位置」，而这里的命中**本来就规规矩矩在行首**。
> 真正的问题是**匹配语义**：把一个更长的词截成了前缀。
> 再加第三道同类型闸（比如缩短行长）只会连真单元一起杀掉，治不了本。

### 病根 B：OCR 噪声整行 → 规则无法分辨

`2c90ff4f3662…磨辊润滑装置….pdf` 是扫描件，走 Tesseract OCR，文本层本身就是乱的：

```
… 回国图目
ETE
la|h
相国四站          ← OCR 把图纸上某处像素认成了这四个字，独占一行
zs!
BEL
…
```

这一行满足「行首 + 短行 + 后缀是站」，**任何基于文本的规则都判它是合法单元名**。
只有词表或人工确认能挡。

### 病根 C：文件名通道把设备名当车间（共 4 例）

文件名本身带「××站/××油站」，被直接当成车间：

| 车间名 | 来源文件名（已脱敏） |
|---|---|
| 液压站 | `7d49cbfb4d75_****-液压站外形图.pdf` |
| 磨辊润滑站 | `411dc0ccb980_****磨辊润滑站外形图.pdf` |
| 减速机润滑站 | `434395375ec0_****减速机润滑站外形图.pdf` |
| 主减速机油站 | `a85547f154fb_****主减速机油站管路布置图.pdf` |

注意这四例置信度是 **0.75**，比正文通道的 0.55 还高 —— 而它们全是错的。
「文件名更可信」这个前提在**设备外形图**这类图纸上不成立：
这类图的文件名主体是设备，不是安装位置。

## 四、修复建议（按优先级；建议全部做，只做 R1 治不完）

### R1 — 单字后缀必须要求右边界（治 A，纯规则可修）

单字后缀（`室/间/站/厂/区/场/仓/房/库`）命中后，**右邻字符不能是汉字**；
否则说明这是更长词的前缀，应当丢弃。

```python
# 命中 m 之后，单字后缀要额外看右边界
_SINGLE = set("室间站厂区场仓房库")
tail = m.group(0)[-1]
if tail in _SINGLE:
    nxt = tn[m.end():m.end() + 1]
    if nxt and "\u4e00" <= nxt <= "\u9fa5":
        continue          # 相对室|外… → 不是边界，丢
```

只这一条就能干掉 `相对室`、`件与件之间`。
`配电室`、`泵站`、`堆场` 这类真单元后面通常跟标点、数字或行尾，不受影响。

### R2 — 设备名后缀进黑名单（治 C，两条通道都要过）

```python
# 这些是设备，不是安装位置
_DEVICE_TAIL = ("液压站", "油站", "润滑站", "泵站"以外的"…站"? 见下, "风机", "泵", "机组",
                "减速机", "磨机", "提升机", "除尘器", "收尘器", "变压器", "开关柜")
```

注意两点：
1. **`泵站` 是真单元**（水处理泵站），不能一刀切按「站」结尾杀 —— 必须用整词黑名单，不能用后缀黑名单。
2. filename 通道必须和 content 通道**共用同一套校验**，不能像现在这样各写各的。

### R3 — 引入「待确认」通道（治 B，这是唯一能挡住 OCR 噪声的办法）

凡是不在白名单词表里的候选，**不要直接写进 `workshop` 字段**：

```json
{
  "workshop": null,
  "status": "pending",
  "candidates": ["相国四站"],
  "confidence": 0.55,
  "evidence": "OCR 文本层第 4 行"
}
```

界面上做成「待确认车间」列表，人工点一下确认或忽略，确认过的进项目词表。
这也符合既定的数据治理红线：**不确定的映射交人判断，AI 不替用户猜**。

### R4 — 断言（已在本仓库加上，见 `selftest.py`「车间名合法」）

任何不以 `车间/工段/装置/系统/厂房/片区/区域/工序` 结尾的车间名一律判可疑。
下一轮该条会报 F1 —— 那是如实反映现状，不是回归。

## 六、验收标准

1. `GET /api/workshops` 在真实资料上返回的车间名，**全部**以工程后缀结尾；
2. `相对室` / `件与件之间` 不再出现（R1）；
3. `液压站` / `磨辊润滑站` / `减速机润滑站` / `主减速机油站` 不再出现（R2）；
4. `相国四站` 这类 OCR 噪声进「待确认」，不直接进车间清单（R3）；
5. 自测「车间名合法」为 PASS；
6. 真车间 `粗碎车间` 仍能正常识别（**不能为了去噪把真单元也杀了**）。

第 6 条是硬约束：宁可少识别，不可乱识别，但也不能因为加了过滤就一个都认不出来。
