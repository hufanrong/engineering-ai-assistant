## 二、修掉的根因（12 条）

标签沿用提交顺序，每条都能在 `workbench/app/config.py` 的 v0.1.226 / v0.1.227 注释里找到完整论证。

### D1 外部工具只搜 C 盘 → 把「本机有」误报成「本机没有」
- 证据：`_find_oda_converter()` 只查 `os.environ["ProgramFiles"]`（恒为 C 盘）+ 写死 `C:\ODA\...`。
  注册表一查：ODA 在 `D:\ODA\`、AutoCAD 2020 在 `D:\Program Files\Autodesk\`。
- 后果：25 张 DWG 全报「未找到 ODA」，60 个文件只有 19 个有正文。
- 修：`_find_external_tools()`，盘符枚举 C..Z + 注册表 `InstallLocation` + 有限通配 + `where`，
  一次查清 ODA / accoreconsole / Tesseract，并把 `searched_roots` 带进报错。
- 验证：同一张图纸 `parsed text=1300 6.3s` / `parsed text=26251 5.9s`。

### D2 自测解释器 ≠ 交付解释器
- 证据：循环用 `sys.executable`，老板双击 `open_or_start.bat` 用 `workbench/venv`。
  实测 venv 有 paddleocr 没 xlrd，宿主内置 python 反之。
- 后果：「我这边 .xls 通过」与「真机 skipped」同时成立，自测结论不代表真机。
- 修：`wb_loop._runtime_python()` venv 优先；`env.json` 同时记录两个解释器与各自包版本。

### D3 `requirements.txt` 漏 `xlrd`
- 证据：`parse_xls` 依赖 xlrd，清单里没有；venv 里确实没有。
- 后果：真机上传 .xls → `ImportError` → `parse_file` 记成 skipped/缺少依赖。
- 修：补 `xlrd>=2.0.1` 并装进 venv。

### D4 自测带着宿主沙箱跑，测的是沙箱不是产品
- 证据：宿主往 `PYTHONPATH` 注入 `sitecustomize`，单轮批量删除 >50 文件直接 `SystemExit(1)`；
  删一个 59 文件的测试项目 → 工作台主进程当场退出 → 整轮级联失败。
- 修：`wb_loop._child_env()` 把 shim 目录从子进程 `PYTHONPATH` 滤掉（只影响为测试创建的进程）。

### D5 删项目能把整个服务带走
- 证据：`delete_project` 一句裸 `shutil.rmtree`；`SystemExit` 不是 `Exception` 子类，拦不住。
- 修：`_safe_rmtree()` —— 重试、收所有 `BaseException`、报残留项，失败返回 `ok=False` 并记审计。

### D6 解析器修好了，老资料不会重新解析（最隐蔽的一条）
- 证据：判重只看 `status=="parsed"`。ODA 修好后，25 张 DWG 缓存里仍是
  `{"status":"partial","text":"","error":"未找到 ODA File Converter…"}`，扫描一律跳过。
- 后果：**这次修复对存量数据完全无效**，用户看到「修了跟没修一样」，且不知道该重传哪些。
- 修：`config.PARSER_VERSION` + 索引/缓存双写版本戳，判重改为「parsed 且是当前版本解析的」；
  新增 `scanner.reparse_stale()` 与 `POST /api/index/reparse` 把差距量化；上传去重同样按版本判。

### D7 `selftest.py` 自己会崩，把崩溃伪装成 6 个功能缺陷
- 证据：phase1 里 `details` 只在 `if items:` 内赋值，后面在分支外读 → `UnboundLocalError`。
- 后果：phase1 整段崩掉 → 样本没入库 → phase3 全部「无设备数据」，6 条红全是下游假象。
- 修：`details/detail_fail` 提前初始化。

### D8 扫描等待写死 240 秒，真实资料永远等不到
- 证据：63 个文件含 25 张 DWG（每张 ODA 转换 ~6s）+ 16 份扫描件，实测 8~20 分钟。
- 修：改按进度等待（最多 30 分钟；`done` 连续 90 秒不动才判卡死）；
  新增「扫描统计可读」断言，区分「没扫完」与「扫完但没 stats」。

### D9 原子写在 Windows 上会被读方阻塞，索引写入静默丢失
- 证据：`test_atomic_write.py [B]`：并发期间 0 次读到损坏文件（PASS）、结束后完整 800 条（PASS）、
  但「0 错误」FAIL —— `PermissionError [WinError 5]`。
- 根因：`MoveFileEx` 要求目标文件没被别的句柄以「不共享删除」方式打开，而 Python `open()` 默认不共享 DELETE。
  于是「扫描在写 index.json」与「页面刷新在读 index.json」一撞，写入方的 replace 就失败；
  调用方普遍 `except Exception: pass` → 文件从资料库静默消失。
- 修：`atomic_io._replace_with_retry`（只对 winerror 5/32/33 重试，40×30ms≈1.2s），
  并把 `scanner` / `completion_archive` / `template_engine` / `upload_queue` 各自抄的那份裸 `os.replace` 统一过去。
- 验证：`test_atomic_io` 22/22、`test_atomic_write` 29/29、`test_index_count` 10/10、`test_archive_concurrency` 13/13。

### D10 单实例锁在 UTF-8 模式下判活走空（机制成立，双开未实测到）
- 证据：`UnicodeDecodeError: 'utf-8' codec can't decode byte 0xd0` 出现在两轮日志开头。
  `tasklist` 在中文 Windows 输出 GBK，`text=True` 不指定编码时按默认编码解码；UTF-8 模式下解码失败，
  异常发生在 subprocess 的 reader **线程**里，不冒泡 → stdout 空 → 判定「pid 不在」→ 覆盖锁。
- 修：`_pid_alive()` 改用 Win32 `OpenProcess`（零解析、零编码），判不出来时按「活着」处理。
- **更正**：我最初看到「两个 wb_loop」就断定已双开，实际是 `venv\Scripts\python.exe` 这个 241KB 启动器
  又拉起真身解释器，「启动器 + 真身」天然成对。后果未实测到，按潜在缺陷记录。

### D11 图签栏恒为 `{}`
- 证据：两张真实 DWG 正文能抽 1300 / 26251 字，`title_block` 却是空。
- 根因：抽取区域假定「图框右下 45%」，模型空间并排多图 / 包围盒被拉远时那片区域什么都没有。
- 修：区域没匹配到键词就**全图再找一遍**，并标 `_source`；区域为空也不再直接 `return {}`。
- 验证：25/25 张 DWG 有图签内容。

### D12 竣工图清稿（阶段 4）第一次真正跑起来，暴露三处
- ① 环境自检说 `ready=true`，一点就 `ModuleNotFoundError`：`ready` 只看 windows/pywin32/pypdf/AutoCAD，
  **从不检查 `tools/dwg_cleaner` 能不能导入**。已改为真 import 一次并计入 ready。
- ② `RPC_E_CALL_REJECTED` 只等 9 秒：`com_error (-2147418111, '被呼叫方拒绝接收呼叫。')`
  是 AutoCAD COM 服务器没准备好，冷启动 60~120 秒。改为 6 次指数退避 ≈150 秒，并在错误里给处置建议。
- ③ 机器上同时有 3 个 `acad.exe`（07:44 / 10:10 / 10:40）—— 多实例共存本身就是 RPC 拒绝的常见诱因。
- 状态：**未完成验证**。AutoCAD 是 GUI 进程，在我的沙箱会话里进程会被终止；
  这一步需要老板在真实桌面上点一次。

### 附带：车间名脏数据
- 证据：`/api/workshops` 返回 `件与件之间` / `相国四站` / `详见厂` / `中矿堆`。
- 根因：`_WORKSHOP_RE` 后缀集含 间/站/厂/区/场 这类高频字，而 `_from_text` 在整篇正文上扫
  （一张流程图 2.6 万字），必然命中句子中间。
- 修：命中必须落在该行第一个非空白字符处 + 所在行 ≤40 字 + `详见/参见/见/依据/根据/按照/如图/见图` 加入拒绝前缀。
- 残留：`相国四站` 这类本身像单元名的碎片仍会通过，需人工确认。

## 三、OCR 现状（说清楚，别当成已解决）

| 项 | 结论 |
|---|---|
| PaddleOCR 3.7.0 + paddlepaddle 3.3.1 | `predict()` 必崩：`ConvertPirAttribute2RuntimeAttribute not support`（oneDNN）。`FLAGS_use_mkldnn=0`、`FLAGS_enable_pir_api=0/1` 三组组合**全部无效** |
| paddle 与 torch 同进程 | 先 `import paddle` 再 `import torch` → `WinError 127 shm.dll`。已在 `_get_ocr()` 里改成先 torch 后 paddleocr |
| Tesseract 5.4 | 原装只有 eng+osd。已随程序带 `workbench/ocrdata/chi_sim.traineddata`（2.4MB，免管理员、离线可用），首次使用时把系统 eng/osd 复制进来 |
| 识别质量 | 工程图纸以尺寸数字/符号为主，Tesseract 噪声大，只能保「搜得到」，不能保「读得准」 |
