## 三、根因（每条都实测复现过）

### C1 · 正文压过文件名，多候选时直接放弃（最主要）

`detect_workshop()` 的优先级是：CAD 标题栏 → **目录路径** → **文件名** → **正文** → 已知车间兜底。

问题在于 `_norm_filename()` 对这类文件名返回 `None`：

```
_norm_filename('0205 熟料粉磨装置-结构图（2025.07.15）-R0.dwg')  →  None
```

它只认「编号-名称」那样的分段，而这种「编号 名称-图种-版本」的写法落不进去。
于是流程掉到第 4 步看正文，正文抽出来是：

```
['螺纹间', '当中间', '螺栓间']
```

三个候选 → 判定「多车间、无法唯一确认」→ **直接 `return {'workshop': None}`**，
**再也不会走到第 5 步的「已知车间兜底」**。

实测（真实缓存正文喂进去）：

```python
detect_workshop(file_name='2cf7b6dc5372_0205 熟料粉磨装置-结构图（2025.07.15）-R0.dwg',
                text=<该文件真实正文>)
# → {'workshop': None, 'source': 'content_multi',
#    'candidates': ['螺纹间', '当中间', '螺栓间']}
```

**文件名里白纸黑字写着「熟料粉磨装置」，却被三个正文碎片挤掉了。**

更关键的是，这份文件的正文**根本没有「熟料粉磨装置」四个字**，它是张化学锚栓参数表：

```
螺纹间距 (mm) | 双螺母(Double nuts) | 露出长度 a(mm) | 螺纹长度 b(mm)
抗拉承载力设计值(kN) | Q235/Q355 | 锚固长度 | 锚板尺寸 | C35 | ≥C40 | M16 ...
```

`螺纹间距`→`螺纹间`、`螺栓间距`→`螺栓间`、一段「…当中间…」→`当中间`。
**正文通道在这类纯构造详图上永远不可能认对**，文件名是唯一有效信号，而它被丢了。

另一种形态（正文里**确实有**车间名，照样放弃）：

```python
detect_workshop(file_name='143081201680_0205-熟料粉磨装置-照明配线平面图-20250718.dwg',
                text=<正文含「熟料粉磨装置」>)
# → {'workshop': None, 'source': 'content_multi',
#    'candidates': ['熟料送存仓', '熟料粉磨装置地下室', '熟料粉磨装置室']}
```

三个候选里两个是**「熟料粉磨装置」加单字后缀**（`地下室`/`室`）——
又是 D13 的切词病。系统认为「这是三个不同车间」，直接放弃。

**结论：只要正文出现 2 个以上候选就 `return None`，而这三个候选本来指向同一个车间。**

### C2 · 子项码没人用（7 个文件因此全落空）

`2A24A47DDA0205ME1PW1-08` 里的 `0205` 就是子项码，对应「熟料粉磨装置」。
这类文件没有中文名，正文也抽不出东西，于是 `source=none`。

实测这 7 个文件的正文长度：`0 / 288 / 309 / 349 / 349 / ...` —— 等于空。
**除了文件名里的 `0205`，系统手上什么都没有。** 而 `0205` 是已知的、现成的映射。

对照：工艺设备表里 `0205` 工作表的「子项名称」写的就是**熟料粉磨装置**——
映射关系在资料里是现成的，程序没去用。

### C3 · 正文碎片与 D13 同源（单字后缀截断）

本次抓到的碎片候选：`螺纹间`、`当中间`、`螺栓间`、`熟料粉磨装置室`、
`熟料粉磨装置地下室`、`相对室`。

和 D13（车间名废字）是**同一个病根**：`_WORKSHOP_RE` 用 `{1,8}?` 惰性匹配配
单字后缀（`室/间/站/厂/区/场/仓/房`），把长词切成前缀。
**修 D13 的 R1（单字后缀要求右边界）可以同时治这里** —— 碎片进不来，
正文候选就干净了，C1 的「多候选」也就不会误触发。

### C4 · 已知车间集被废字污染

```python
_known_set()  →  ['熟料粉磨装置', '相对室', '粗碎车间']
```

`相对室` 进去了。它一旦在已知集合里，往后**任何文件名/路径里含「相对室」三个字
的文件都会被归到「相对室」**，污染会自我繁殖。

`_known_set()` 应该只收「工程后缀合法 + 用户确认过」的名字。

### C5 · `re_auto_unassigned()` 覆盖不全

我手动跑了一次 `/api/workshop/re-auto`，只补进 5 个（41 → 46），
剩下 3 个 `content_multi` 的和 7 个只有编码的依然纹丝不动 ——
因为前者卡在 C1（重跑还是同样的短路），后者卡在 C2（没有子项码逻辑）。
**这不是「没触发重算」，是「重算了也算不出来」**，得改判定逻辑本身。

## 四、修复建议

### R1 · 已知车间兜底提到正文之前（治 C1，收益最大）

文件名/路径里**直接出现已知车间名**时，这就是最强信号，不该被正文覆盖：

```python
# 在「看正文」之前插一步：已知车间名命中文件名或路径
known = _known_set()
hay = f"{file_path or ''} {file_name or ''}"
for w in sorted(known, key=len, reverse=True):
    if w and w in hay:
        return {"workshop": w, "source": "known_name", "confidence": 0.85,
                "candidates": [w]}
```

同时把第 4 步的多候选改成**降级**而不是**放弃**：正文多候选 → 记 candidates →
继续往 known 兜底走，而不是 `return None`。

### R2 · 子项码映射（治 C2）

识别两种形态：`DDA(\d{4})`、行首 `^(\d{4})[\s\-_·]`。
映射来源按优先级：
1. 项目内**自学**：同一项目里出现 `0205 XX装置` → 学到 `0205 = XX装置`；
2. 工艺设备表的 sheet 名 + 抬头「子项名称」（`0205` → `熟料粉磨装置`）；
3. 人工确认一次后写进项目映射表，之后长期生效。

置信度给 0.8（低于文件名直命中、高于正文）。

### R3 · `_norm_filename` 要认「编号 名称-图种-版本」这种写法（治 C1 的根）

```
0205 熟料粉磨装置-结构图（2025.07.15）-R0.dwg
└┬─┘ └────┬────┘
子项码      单元名（本该抽出「熟料粉磨装置」）
```

现在返回 `None`。建议：先剥子项码 → 在剩余片段里用 `_WORKSHOP_RE` 找
「以工程后缀结尾且右边界合法」的最长片段。

### R4 · known 集合只收合法名（治 C4）

`_known_set()` 加入过滤：必须以 `车间/工段/装置/系统/厂房/片区/区域/工序` 结尾
（或用户显式确认过）。`相对室` 这类自动清出去。

### R5 · 增加「项目级 / 全厂」类别（治 C5 的混肴）

设备清单、设备表、总图、工艺流程图 → 归「项目级」，不参与车间统计，
界面上单独一栏。现在它们躺在「未归类」里，和真正失败的混在一起，用户没法分辨。

### R6 · 复用 D13 的 R1（单字后缀右边界）

一处修好，D13 的废字和这里的碎片候选一起消失。

## 五、验收标准

1. 熟料粉磨装置 ≥ **56/62**（现在 46，差 10）；
2. **`7df8d3ccd3dc_0205-熟料粉磨装置-防雷接地.dwg` 归到熟料粉磨装置**，
   不再归「相对室」（现在是归错，比漏归严重）；
3. 未归类只剩**项目级 3 个**，且它们被标成「项目级/全厂」而不是「未归类」；
4. `相对室` 不再出现在车间清单里，也不在 `_known_set()` 里；
5. **自动归类覆盖率 ≥ 50%**（现在系统只出手 10/62 = 16%，其中对 9 个）；
6. 人工指定占比从 63%（39/62）降到 **≤ 20%**；
7. 7 个 `DDA0205…` 文件全部归到熟料粉磨装置；
8. 3 个 `content_multi` 文件（文件名含熟料粉磨装置）全部归对；
9. 自测基准车间变成**熟料粉磨装置**（资料最多的车间），不再是只有 2 份资料的粗碎车间；
10. 回归：`_WORKSHOP_RE` 对 2.3 节那份防雷接地正文的命中数从 16 降到 **0**。
