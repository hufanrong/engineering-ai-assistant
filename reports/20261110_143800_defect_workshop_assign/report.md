## 三个最硬的证据

**1. 文件名写着车间名，被三个正文碎片挤掉**

```
文件：2cf7b6dc5372_0205 熟料粉磨装置-结构图（2025.07.15）-R0.dwg
正文：化学锚栓参数表（螺纹间距 / 双螺母 / 抗拉承载力 / 锚板尺寸）—— 根本不含「熟料粉磨装置」
结果：{'workshop': None, 'source': 'content_multi',
       'candidates': ['螺纹间', '当中间', '螺栓间']}
```

`_norm_filename()` 对这种「编号 名称-图种-版本」形态返回 `None`，于是掉到正文；
正文抽出三个锚栓术语碎片 → 判「多车间」→ **直接 `return None`，再也不走 known 兜底**。
**这类纯构造详图的正文永远认不出车间，文件名是唯一信号，而它被丢了。**

**2. 归错比漏归严重**

```
文件：7df8d3ccd3dc_0205-熟料粉磨装置-防雷接地-20240116.dwg
结果：workshop='相对室'  source='content'  confidence=0.55
```

「相**对室**外地坪高度」被 `_WORKSHOP_RE` 切成「相对室」，命中 3 次成了最强候选。
同一份正文里这个 regex 一共命中 **18 次，18 个全是废字**（金属板间 / 二者之间 / 桥架全厂 / 各引下线外墙距室 …）。
**废字率 100%。**

**3. 废字已经进了已知集合，会自我繁殖**

```python
_known_set()  →  {'熟料粉磨装置', '粗碎车间', '相对室'}
```

`相对室` 一旦进来，往后任何文件名/路径含「相对室」三个字的文件都会被吸过去。

## 根因

| 代号 | 根因 | 文件 · 位置 |
|---|---|---|
| C1 | 已知车间兜底排在正文之后，且正文多候选即放弃（`return None` 短路掉兜底） | `workshop_assign.py` · `detect_workshop()` |
| C2 | 无子项码映射，`0205` / `DDA0205` 现成对应「熟料粉磨装置」但没用 | 同上 |
| C3 | `_norm_filename()` 只认「编号-名称」，不认「编号 名称-图种-版本」 | `workshop_assign.py` · `_norm_filename()` |
| C4 | `_known_set()` 收废字，无工程后缀校验 | `workshop_assign.py` · `_known_set()` |
| C5 | `_WORKSHOP_RE` 单字后缀（室/间/站/厂/区/场/仓/房）无右边界 —— **与 D13 同一个病根** | `workshop_assign.py` · `_WORKSHOP_RE` |

7 个 `2A24A47DDA0205ME1PW1-xx` 文件正文长度 **0 ~ 349**，等于空，唯一线索就是文件名里的 `0205`。

## 修复要点（详见档案第四节，共 6 条 R1~R6）

1. **R1** 文件名/路径命中已知车间名时，优先级提到正文之前；正文多候选改成**降级**（记 candidates 继续往 known 兜底）而不是放弃；
2. **R2** 子项码映射：`DDA(\d{4})` / 行首 `^(\d{4})[\s\-_·]`，映射来源优先项目内自学（`0205 XX装置`），其次工艺设备表 sheet 名+「子项名称」，再次人工确认一次长期生效；
3. **R3** `_norm_filename` 先剥子项码，再在剩余片段里按「合法右边界的最长工程后缀片段」取名；
4. **R4** `_known_set()` 只收以 `车间/工段/装置/系统/厂房/片区/区域/工序` 结尾的名字；
5. **R5** 新增「项目级 / 全厂」类别 —— 设备清单、设备表、总图、工艺流程图归这里，不参与车间统计；现在它们和真正失败的混在「未归类」里；
6. **R6** 复用 D13 的 R1（单字后缀要求右边界），一处修好，D13 废字与本单 18 个碎片一起消失。

## 本单同时落地的自测改动（v0.1.231）
