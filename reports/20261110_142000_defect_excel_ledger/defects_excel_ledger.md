# 缺陷档案 · 工艺设备表整张作废，614 个真实位号丢失（D14）

| 项 | 值 |
|---|---|

| 被测版本 | `0.1.230`（commit `e2b85c7`） |

| 触发文件 | `28172857098f_…工艺设备表（0430).xlsx`（10 个工作表） |
| 结论 | **这份最有价值的表整张没被用上，614~753 个真实位号全部丢失** |

---

## 一、结论先说

| 指标 | 现状 | 这份表能给的 |
|---|---|---|
| 设备台账台数 | **24** | **614**（严格口径）/ **753**（宽松口径） |
| 位号（tag）非空率 | **0%**（全部 `_no_tag_`） | 每个设备都有工程位号 |
| 车间/单元数 | 2（粗碎车间、中矿堆） | **10 个子项** |
| 竣工「设备安装记录」 | 「设备位号：【待补充】」 | 自动带出位号 |

后果很直接：**现在出具的所有竣工记录表，设备位号一栏全是「【待补充】」**。
位号是竣工资料的命门 —— 没有位号，资料员只能手工翻图纸一个个填，这套系统等于
「生成了一个漂亮的空壳」。

## 二、证据

### 2.1 文件结构（设计院标准格式，不是坏文件）

`0101` 工作表，195 行 × 252 列：

| 行 | 内容 |

| 2 | `G2=设计证书`　`J2=A111008557` |
| 3 | `A3=项目名称`　`B3=马诺诺锂业…锂盐项目`　`G3=版本`　`I3=R0` |

### 2.3 三种不同布局，都得认

同一个文件里三种表结构并存：

| 布局 | 表头行 | 特征 |
|---|---|---|
| A（0101/0103/0104/0202/0203/0204/0205） | 第 6 行 | `A6=设备编号`，数据行带**子行**（`规格`/`功率`/`电机` 单独占行） |
| B（0201） | 第 6 行 | `B6=名称规格型号`（名称与型号合一），位号规约不同，行内带 `一 HX0201ME01` 这类章节标记前缀 |
| C（0201-尘硝一体 / 脱硫脱氟） | 第 6 行 | 分级编号 `1` / `1.1` / `1.1.1`，**无位号**，名称在 `D` 列 |

### 2.4 现在解析成了什么

`parsed_cache/28172857098f….json` 里：

```json
"header": ["列1", "设备表", "列3", "列4", "列5", "列6", "项目代码", "列8",
           "列9", "2A24A47", "列11", ... ]
```

**表头 = 第 1 行的抬头块**，于是第 6 行真正的列名（设备编号/规格型号/单位/数量）
一个都没当上列名，整张表退化成 252 个 `列N`。台账自然一台都取不到。

## 三、根因

`workbench/parsers/engines.py` · `parse_excel()`

```python
all_rows = [list(r) for r in rows_iter if any(...)]
header = _normalize_header([... for v in all_rows[0]])   # ← 无条件把第 1 行当表头
```

第 1 行是抬头块（「设备表 / 项目代码 / 2A24A47」），不是列名。
`_normalize_header` 本身没问题（合并单元格、BOM、去重都做了），问题是**喂给它的行选错了**。

这与之前 D13（车间名）是同一类病：**在「格式规整的合成样本」上验证通过，
到了设计院真实表格上，前提假设就不成立。** 合成样本永远把表头放第 1 行。

---

## 四、影响链（不是只丢一张表）

1. **台账规模**：24 → 614，差 25 倍；
2. **位号全空** → 竣工记录表每一张都印「设备位号：【待补充】」；
3. **组卷**：现在只组出 2 卷（粗碎车间、中矿堆），因为只有那份简单清单有「车间」列；
   吃下这份表后应能按 10 个子项组卷；
4. **按车间统计 / 缺件清单 / 覆盖率**：全部建立在台账之上，一起失真；
5. **设备与图纸的关联**：位号是图和设备之间的唯一纽带，没有位号就没法做
   「设备 → 图纸」的自动挂接，这正是老板要的 2.5D 空间语义图的前置条件。

---

## 五、修复建议

### R1 — 表头行探测（核心）

不要取第 1 行，改为**在前 20 行里找列名密度最高的那一行**：

```python
_HEADER_KEYS = ("设备编号", "位号", "名称", "规格", "型号", "单位", "数量",
                "功率", "重量", "备注", "技术参数", "材质")
best = max(range(min(20, len(all_rows))),
           key=lambda i: sum(1 for v in all_rows[i]
                             if any(k in str(v or "") for k in _HEADER_KEYS)))
header_idx = best if 命中数(best) >= 3 else 0      # 少于 3 个关键词就退回第 1 行
```

阈值取 3 是为了不把普通表格误判（普通表第 1 行本来就命中≥3，不受影响）。

### R2 — 抬头块当元数据，不要当表头

表头行**上方**的单元格抽成 sheet 级元数据：

```json
{"sheet": "0101", "meta": {
   "子项名称": "锂辉石库", "项目名称": "马诺诺锂业…",
   "文件编码": "2A24A47DDA0101ME1M…", "版本": "R0"}}
```

子项名称直接就是车间/单元名，价值极高 —— 而且它们都以 `库 / 装置 / 车间` 结尾，
正好能通过新加的「车间名合法」校验。

### R3 — 子行归属（否则数量会翻倍虚高）

布局 A 里 `规格`、`功率`、`电机` 是**子行**，A 列为空：

```
A7=SR0101ME01A  B7=料斗      G7=台  H7=1
A8=(空)         B8=储量      C8=60  G8=m³
A9=SR0101ME01A-MK1 B9=振打器  G9=套  H9=2
```

A 列为空的行要**向上挂到最近的非空位号**，作为该设备的附加参数；不能自己当一台设备。

### R4 — 位号识别要容多种规约

至少三种：`SR0101ME01A`（子项码+专业+序号）、`P01-RV-01`、`SR0101ME01A-MK1`（部件）。
建议：`^[A-Za-z][A-Za-z0-9]{1,}](-[A-Za-z0-9]+)+$` 之类**按结构**判，不要枚举前缀。
另外 `一 HX0201ME01` 这种带中文序号前缀的，先剥掉 `^[一二三四五六七八九十]+\s*`。

### R5 — 多份台账要合并去重

`选厂设备清单1.xlsx`（24 台，有「车间」列，无位号）和这份工艺设备表（614 台，有位号）
**是互补的**：前者给车间归属和厂家，后者给位号和技术参数。
合并键：设备名称 + 型号/规格；合并后 24 台不能丢。

> 顺带说明：现台账里的「中矿堆」是 `选厂设备清单1.xlsx` 车间列**原值**，
> 不是解析错误，不要改。

## 六、验收标准

1. 该项目 `device_count` ≥ **600**（严格 614，宽松 753）；
2. 位号（tag）非空率 ≥ **90%**；
3. 车间/单元数 ≥ **7**（锂辉石库、锂辉石烘干、锂辉石计量、回转窑中装置、
   回转窑头装置、熟料送存仓、熟料粉磨装置）；
4. 生成「设备安装记录」，表格里**不再出现**「设备位号：【待补充】」；
5. `选厂设备清单1.xlsx` 的 24 台设备仍在台账里（合并不许丢数据）；
6. 子行（规格/功率/电机）没有被单独算成设备；
7. 自测阶段 3「竣工资料统计 total_devices」随之 ≥ 600，组卷卷数 ≥ 7。
